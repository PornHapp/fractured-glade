# Границы и рамки MVP игры

## Общая концепция

Игра представляет собой **2D sandbox-survival**, вдохновлённый Terraria по игровому процессу, управлению, интерфейсу и общему ощущению от игры, но с собственной центральной механикой - существованием двух Макробиомов одного мира.

Игрок исследует процедурно сгенерированный мир, который существует одновременно в двух вариантах:

1. **Свет** - привычный, живой и безопасный мир.
2. **Тьма** - испорченная версия этого же мира, изменённая визуально и геймплейно.

Эти два Макробиома существуют независимо друг от друга, однако описывают одну и ту же карту мира.

Перемещение между ними осуществляется через специальные объекты - **Разломы**. Проходя через Разлом, игрок меняет текущий Макробиом, оставаясь в тех же мировых координатах.

Таким образом игрок постоянно исследует одну и ту же местность, но в двух разных состояниях.

При этом каждый Макробиом обладает собственными:

- визуальным оформлением;
- противниками;
- ресурсами;
- поведением отдельных объектов;
- атмосферой;
- игровыми механиками.

Некоторые материалы, предметы и пути прохождения доступны только в одном из Макробиомов, поэтому полноценное развитие невозможно без регулярных переходов между Светом и Тьмой.

Игра сохраняет философию Terraria:

- исследование мира;
- добыча ресурсов;
- строительство;
- крафт;
- развитие персонажа;
- свободный стиль прохождения.

При этом основной отличительной особенностью становится не количество контента, а постоянное взаимодействие игрока с двумя версиями одного и того же мира.

## Понимание MVP

Цель MVP - подтвердить работоспособность главной идеи игры и заложить архитектуру, пригодную для дальнейшего масштабирования.

### 1. Главное меню

Реализовать минимальное, но полноценное главное меню.

Функционал:

- Новая игра

  - генерация мира;
  - размер мира: **Маленький**;
  - сложность: **Лёгкая**.
- Настройки

  - громкость музыки;
  - громкость звуковых эффектов.
- Выход из игры.

### 2. Генерация мира

Процедурная генерация небольшого мира.

На этапе MVP достаточно:

- подбиом (Лес);
- подбиом (Простые пещеры);
- поверхность;
- деревья;
- один вид руды.

После генерации автоматически создаются две версии мира:

- Свет;
- Тьма.

Обе версии имеют одинаковую основу, но отличаются наполнением и отдельными игровыми особенностями.

### 3. Макробиомы

Система двух Макробиомов:

- Свет;
- Тьма.

Игрок всегда находится только в одном Макробиоме. При старте игры в Макробиоме Свет.

Переключение осуществляется через Разломы.

Каждый Макробиом использует собственные:

- тайлы;
- декорации;
- освещение;
- атмосферу;
- свойства отдельных объектов;
- набор противников.

### 4. Разломы

Реализовать систему Разломов.

При взаимодействии с Разломом:

- игрок сохраняет мировые координаты;
- происходит смена текущего Макробиома;
- загружается соответствующее состояние мира.

Именно эта механика является центральной особенностью игры.

### 5. Игрок

Минимальный набор возможностей:

- движение;
- прыжок;
- добыча блоков;
- установка блоков;
- взаимодействие с объектами;
- использование предметов.

### 6. Инвентарь

Минимальная система инвентаря, аналогичная Terraria:

- хотбар;
- основной инвентарь;
- подбор предметов;
- стакование;
- перенос предметов между слотами.

### 7. Крафт

Минимальный набор рецептов:

- верстак;
- деревянные инструменты;
- каменные инструменты;
- предмет, необходимый для дальнейшего прогресса (при необходимости).

### 8. Ресурсы

Минимальный набор:

- дерево;
- земля;
- камень;
- одна руда.

При этом некоторые ресурсы могут иметь различные свойства или способы получения в зависимости от Макробиома.

### 9. Враги

Минимум два базовых противника:

- обычный слизень (Свет);
- испорченный слизень (Тьма).

Необходимо проверить работу боевой системы и различия между Макробиомами.

### 10. NPC

Один простой NPC.

Цель:

- проверка системы диалогов;
- взаимодействия;
- подготовки архитектуры под дальнейшее развитие.

### 11. Боевая система

Минимальная реализация:

- меч;
- кирка;
- топор;
- здоровье;
- получение урона;
- смерть противников.

### 12. Сохранение

Сохранять:

- мир;
- состояние обоих Макробиомов;
- положение игрока;
- текущий Макробиом;
- инвентарь.

### 13. Архитектура проекта

С самого начала необходимо придерживаться масштабируемой архитектуры.

Основные требования:

- чёткое разделение игровых систем;
- модульная структура проекта;
- независимые менеджеры игровых подсистем;
- возможность дальнейшего добавления новых биомов, предметов и сущностей без переработки существующего кода.

### 14. Технические требования

Разработка ведётся с соблюдением инженерных практик.

Обязательно:

- Godot 4.x
- GDScript
- Git
- GitHub
- понятная структура проекта;
- единый Code Style;
- использование ресурсов (`Resource`) для игровых данных;
- разделение данных и логики;
- масштабируемая архитектура;
- документирование основных систем.

### 15. Инструменты разработки

Для ускорения разработки и тестирования необходимо сразу реализовать внутренние инструменты.

Например:

#### 15.1. Debug System

- отображение FPS;
- отображение координат игрока;
- отображение текущего Макробиома;
- отображение активного биома;
- отображение сидов генерации;
- режим свободной камеры.

#### 15.2. Cheat System

Комбинации клавиш или консоль:

- бессмертие;
- полёт;
- ускорение игрока;
- ускорение времени;
- выдача любого предмета;
- телепортация;
- смена Макробиома;
- открытие всей карты;
- отключение коллизий.

Такие инструменты значительно ускорят тестирование и дальнейшую разработку.

### 16. Что остаётся за рамками MVP

Сознательно исключаются:

- полноценный сюжет;
- квестовая система;
- боссы;
- таверна;
- большое количество NPC;
- дополнительные подбиомы;
- данжи;
- магия;
- погодные эффекты;
- жидкости;
- проводка;
- фермерство;
- рыбалка;
- питомцы;
- маунты;
- сложная экономика;
- мультиплеер.

При этом **архитектура проекта должна сразу учитывать будущий мультиплеер**. Это означает минимизацию глобального состояния, чёткое разделение данных и представления, а также проектирование игровых систем так, чтобы в будущем их можно было синхронизировать по сети без полной переработки логики.

### 17. Критерий успешного MVP

MVP можно считать успешным, если игрок способен пройти полный базовый цикл игры:

1. Создать новый процедурно сгенерированный мир через главное меню.
2. Исследовать Светлый Макробиом.
3. Добыть первые ресурсы и создать базовые инструменты.
4. Найти Разлом и перейти в Тёмный Макробиом.
5. Исследовать ту же область мира в её искажённом состоянии.
6. Столкнуться с отличиями в окружении, ресурсах и противниках.
7. Вернуться обратно и использовать полученные материалы для дальнейшего развития.

Если после этого возникает желание продолжать исследование обеих версий мира, значит основная механика и фундамент проекта работают. Всё последующее развитие - новые биомы, NPC, сюжет, боссы, экономика и мультиплеер - будет расширять уже проверенную основу, а не пытаться исправить её.
